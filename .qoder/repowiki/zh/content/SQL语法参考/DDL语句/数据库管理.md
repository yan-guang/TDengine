## CREATE DATABASE 语句

### 语法结构

`CREATE DATABASE` 语句用于创建一个新的数据库。其完整语法结构如下：

```sql
CREATE DATABASE [IF NOT EXISTS] db_name [db_options];
```

其中 `db_options` 是一个可选的参数列表，可以包含多个配置项，用空格分隔。

**语法来源**
- [sql.y](file://source/libs/parser/inc/sql.y#L189-L250)

### 参数详解

`CREATE DATABASE` 语句支持以下可配置参数，每个参数都对数据库的性能、存储和行为有直接影响。

| 参数 | 作用 | 取值范围 | 默认值 | 性能影响 |
| :--- | :--- | :--- | :--- | :--- |
| `WAL_LEVEL` | 控制写前日志（WAL）的级别，影响数据持久性和写入性能。 | `1`, `2` | `1` | `WAL_LEVEL=2` 提供更强的数据持久性，但写入性能略低；`WAL_LEVEL=1` 写入性能更高，但持久性稍弱。 |
| `CACHE` | 设置数据库的缓存大小（单位：MB）。 | `100` ~ `10485760` | `16` | 缓存越大，查询性能越好，但占用内存越多。 |
| `KEEP` | 定义数据的保留时间，可以指定多个阶段。 | `1d` ~ `365000d` | `3650d,3650d,3650d` | 保留时间越长，存储成本越高。多阶段保留（如 `KEEP 30,30,30`）可用于实现数据生命周期管理。 |
| `BLOCKS` | 设置每个数据块中的行数。 | `3` ~ `1000` | `6` | 块越大，压缩率越高，但写入延迟可能增加。 |
| `PRECISION` | 设置时间戳的精度。 | `'ms'`, `'us'`, `'ns'` | `'ms'` | 精度越高，存储空间占用越大，但时间分辨率更高。 |
| `QUORUM` | （3.0 版本不支持）设置写入操作的确认数。 | `1`, `2` | `1` | N/A |
| `REPLICA` | 设置数据库的副本数，用于高可用。 | `1`, `3` | `1` | 副本数越多，系统可用性越高，但写入性能会下降。 |
| `DAYS` | 设置数据文件的持续时间（即一个文件包含多少天的数据）。 | `60m` ~ `min(3650d,keep)` | `10d` | 持续时间越短，小文件越多，可能影响查询性能；持续时间越长，单个文件越大，可能影响写入性能。 |
| `MINROWS` | 设置一个数据块中最小的行数。 | `10` ~ `1000` | `100` | 影响数据块的填充效率和压缩率。 |
| `MAXROWS` | 设置一个数据块中最大的行数。 | `200` ~ `10000` | `4096` | 与 `BLOCKS` 共同作用，控制数据块的大小。 |
| `FSYNC` | 设置 WAL 文件的同步周期（单位：毫秒）。 | `0` ~ `180000` | `3000` | 值越小，数据越安全，但 I/O 压力越大；值为 `0` 表示禁用同步，性能最高但风险最大。 |
| `COMP` | 设置数据压缩级别。 | `0`, `1`, `2` | `2` | 压缩级别越高，存储空间越小，但 CPU 消耗越高。 |
| `CACHEMODE` | 设置缓存模式。 | `'node'`, `'last_row'`, `'last_value'`, `'both'` | `'node'` | 影响查询缓存策略，`'last_value'` 和 `'both'` 对于频繁查询最新值的场景有显著性能提升。 |
| `ABLOCK` | （已弃用）设置异步块大小。 | N/A | N/A | N/A |
| `TSDBBLOCK` | （已弃用）设置 TSDB 块大小。 | N/A | N/A | N/A |
| `TTL` | 设置数据的生存时间。 | `1` ~ `∞` | `1` | 与 `KEEP` 类似，但更侧重于自动清理。 |
| `MINSTTABLES` | （已弃用）设置最小超级表数量。 | N/A | N/A | N/A |
| `MAXSTTABLES` | （已弃用）设置最大超级表数量。 | N/A | N/A | N/A |
| `SINGLE_STABLE` | 设置是否为单超级表模式。 | `0`, `1` | `0` | 在单超级表模式下，数据库优化针对单一超级表场景，可能提升特定查询性能。 |

### 使用示例

以下是一些 `CREATE DATABASE` 语句的使用示例：

```sql
-- 创建一个名为 'demo' 的数据库，使用默认配置
CREATE DATABASE demo;

-- 创建一个名为 'sensor_data' 的数据库，配置高精度、高副本和长数据保留
CREATE DATABASE sensor_data 
PRECISION 'ns' 
REPLICA 3 
KEEP 3650,1825,365 
DAYS 1d 
MINROWS 1000 
MAXROWS 8192 
WAL_LEVEL 2 
COMP 2 
CACHEMODE 'both';
```

### 默认配置与最佳实践

当不指定任何选项时，`CREATE DATABASE` 会使用一组默认配置。这些默认值旨在为大多数场景提供良好的平衡。

**最佳实践建议：**
- **高写入吞吐场景**：可以考虑将 `WAL_LEVEL` 设为 `1`，`FSYNC` 设为 `0`（仅在可接受数据丢失风险时），并适当增加 `MAXROWS`。
- **高查询性能场景**：应使用较大的 `CACHE`，并根据查询模式选择合适的 `CACHEMODE`（如 `'last_value'`）。
- **长期数据存储场景**：合理配置 `KEEP` 的多阶段策略，例如 `KEEP 30,365,3650`，以实现热、温、冷数据的分层存储。
- **高可用场景**：必须将 `REPLICA` 设为 `3`，以确保在单个节点故障时服务不中断。

## ALTER DATABASE 语句

### 语法结构

`ALTER DATABASE` 语句用于修改现有数据库的配置。其语法结构如下：

```sql
ALTER DATABASE db_name alter_db_options;
```

其中 `alter_db_options` 是一个或多个可修改的参数。

**语法来源**
- [sql.y](file://source/libs/parser/inc/sql.y#L190-L250)

### 可修改参数

并非所有在 `CREATE DATABASE` 中可用的参数都可以通过 `ALTER DATABASE` 修改。根据代码分析，以下参数是可修改的：

- `BUFFER`
- `CACHEMODEL`
- `CACHESIZE`
- `WAL_FSYNC_PERIOD`
- `KEEP`
- `PAGES`
- `REPLICA` / `REPLICAS`
- `WAL_LEVEL`
- `STT_TRIGGER`
- `MINROWS`
- `WAL_RETENTION_PERIOD`
- `WAL_RETENTION_SIZE`
- `SS_KEEPLOCAL`
- `SS_COMPACT`
- `KEEP_TIME_OFFSET`
- `ENCRYPT_ALGORITHM`
- `COMPACT_INTERVAL`
- `COMPACT_TIME_RANGE`
- `COMPACT_TIME_OFFSET`

**可修改参数来源**
- [sql.y](file://source/libs/parser/inc/sql.y#L252-L298)

### 使用示例

```sql
-- 修改数据库 'demo' 的副本数为 3
ALTER DATABASE demo REPLICA 3;

-- 修改数据库 'demo' 的数据保留策略
ALTER DATABASE demo KEEP 30,90,365;
```

## DROP DATABASE 语句

### 语法结构

`DROP DATABASE` 语句用于删除一个数据库及其所有数据。其语法结构如下：

```sql
DROP DATABASE [IF EXISTS] db_name [FORCE];
```

- `IF EXISTS`：如果数据库不存在，不报错。
- `FORCE`：强制删除，即使数据库正在被使用。

**语法来源**
- [sql.y](file://source/libs/parser/inc/sql.y#L190-L250)

### 使用示例

```sql
-- 删除名为 'demo' 的数据库
DROP DATABASE demo;

-- 如果存在则删除名为 'temp_db' 的数据库
DROP DATABASE IF EXISTS temp_db;
```
