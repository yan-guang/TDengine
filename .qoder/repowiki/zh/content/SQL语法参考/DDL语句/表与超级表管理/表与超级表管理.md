## 超级表（STABLE）概念详解
超级表（Super Table, STABLE）是TDengine数据库中一个核心的创新概念，专为高效处理海量物联网设备数据而设计。它并非一个存储实际数据的物理表，而是一个**元数据模板**。

一个超级表由两部分定义：
1.  **度量（Metric）列**：定义了所有子表共有的、用于存储时序数据的列，例如`ts`（时间戳）、`temperature`（温度）、`humidity`（湿度）等。
2.  **标签（TAGS）列**：定义了用于描述子表（即具体设备）静态属性的列，例如`location`（位置）、`type`（设备类型）、`model`（型号）等。

通过创建一个超级表，用户可以定义一个统一的数据结构。随后，可以基于这个超级表创建无数个**子表（Child Table）**，每个子表都继承超级表的度量列定义，并拥有自己唯一的标签值。这种设计实现了数据的高效存储和查询，因为相同度量的数据被物理上聚集在一起，而标签则用于快速过滤和聚合。

## CREATE STABLE 语法
`CREATE STABLE`语句用于创建一个超级表。其完整语法结构如下：

```sql
CREATE STABLE [IF NOT EXISTS] table_name 
    (column_def_list) 
    TAGS (tag_def_list) 
    [table_options];
```

*   **`IF NOT EXISTS`**: 可选子句。如果指定的超级表已存在，则不会报错，而是直接返回成功。
*   **`table_name`**: 超级表的名称。
*   **`column_def_list`**: 度量列的定义列表，格式为`column_name data_type`。至少需要定义一个度量列，其中通常包含一个`TIMESTAMP`类型的列作为时间戳。
*   **`TAGS (tag_def_list)`**: 标签列的定义列表，格式同样为`column_name data_type`。标签列用于描述子表的静态属性。
*   **`table_options`**: 可选的表级配置，如`COMMENT`（注释）、`TTL`（生存时间）等。

**示例**:
```sql
-- 创建一个名为 `weather_stable` 的超级表，包含温度、湿度等度量，以及位置、设备ID等标签。
CREATE STABLE weather_stable (
    ts TIMESTAMP,
    temperature FLOAT,
    humidity INT,
    pressure DOUBLE
) TAGS (
    location BINARY(20),
    device_id BINARY(10),
    is_active BOOL
) COMMENT '天气数据超级表';
```

此命令的语法定义在`sql.y`文件中，对应的语法规则为：
```
cmd ::= CREATE STABLE not_exists_opt(A) full_table_name(B)
  NK_LP column_def_list(C) NK_RP tags_def(D) table_options(E).
```

## CREATE TABLE 语法
`CREATE TABLE`语句具有双重用途：创建普通表和创建子表。

### 创建普通表
创建一个独立的、不继承任何超级表的普通表。
```sql
CREATE TABLE [IF NOT EXISTS] table_name 
    (column_def_list) 
    [table_options];
```
这与传统关系型数据库的建表方式类似。

### 创建子表
创建一个继承自超级表的子表。这是`CREATE TABLE`在TDengine中最常见的用法。
```sql
CREATE TABLE [IF NOT EXISTS] table_name 
    USING stable_name 
    [specific_cols_opt] 
    TAGS (tag_value_list);
```

*   **`USING stable_name`**: 指定该子表所基于的超级表。
*   **`TAGS (tag_value_list)`**: 为该子表的标签列提供具体的值。标签值的顺序和类型必须与超级表中定义的标签列完全匹配。

**示例**:
```sql
-- 基于 weather_stable 超级表，创建一个名为 `beijing_station_01` 的子表，并为其标签赋值。
CREATE TABLE beijing_station_01 
    USING weather_stable 
    TAGS ('Beijing', 'BS001', true);
```

此命令的语法定义在`sql.y`文件中，对应的语法规则为：
```
cmd ::= CREATE TABLE not_exists_opt(B) USING full_table_name(C)
  NK_LP tag_list_opt(D) NK_RP FILE NK_STRING(E). 
```
（注：此处`FILE`子句为特定用法，创建子表的核心规则是`USING ... TAGS ...`）

## ALTER TABLE 语法
`ALTER TABLE`语句用于修改表的结构。当作用于超级表时，其修改会**自动同步**到所有已创建的子表。

### 修改超级表（ALTER STABLE）
```sql
ALTER STABLE table_name alter_table_options;
```
支持的修改操作包括：
*   **添加列**: `ADD COLUMN column_name data_type`
*   **删除列**: `DROP COLUMN column_name`
*   **修改列**: `MODIFY COLUMN column_name data_type` (通常用于修改`BINARY`或`NCHAR`的长度)
*   **重命名列**: `RENAME COLUMN old_name new_name`
*   **添加标签**: `ADD TAG tag_name data_type`
*   **删除标签**: `DROP TAG tag_name`
*   **修改标签**: `MODIFY TAG tag_name data_type` (通常用于修改`BINARY`或`NCHAR`的长度)
*   **重命名标签**: `RENAME TAG old_name new_name`
*   **设置标签值**: `SET TAG tag_name = value` (直接修改子表的标签值)

**示例**:
```sql
-- 为 weather_stable 超级表添加一个新的度量列 `wind_speed`
ALTER STABLE weather_stable ADD COLUMN wind_speed FLOAT;

-- 为 weather_stable 超级表添加一个新的标签列 `firmware_version`
ALTER STABLE weather_stable ADD TAG firmware_version BINARY(10);

-- 将子表 beijing_station_01 的 location 标签值从 'Beijing' 改为 'Haidian'
ALTER TABLE beijing_station_01 SET TAG location = 'Haidian';
```

这些操作的语法定义在`sql.y`文件中，对应的语法规则为`alter_table_clause`系列规则。

## DROP TABLE 语法
`DROP TABLE`语句用于删除表。

```sql
DROP TABLE [WITH] multi_drop_clause;
```

*   **`WITH`**: 可选子句，用于指定删除行为。
*   **`multi_drop_clause`**: 可以指定一个或多个要删除的表名。

当删除一个超级表时，其所有子表也会被**级联删除**。删除一个子表则只影响该子表本身。

**示例**:
```sql
-- 删除名为 `beijing_station_01` 的子表
DROP TABLE beijing_station_01;

-- 删除名为 `weather_stable` 的超级表及其所有子表
DROP STABLE weather_stable;
```

## 超级表与子表关系及数据模型优势
超级表与子表之间的关系是TDengine高性能的关键。它们之间的关系和优势如下：

1.  **数据模型优势**:
    *   **高效存储**: 所有子表中相同度量（如`temperature`）的数据在物理上被存储在一起，形成了一个巨大的、连续的数据块。这极大地提高了数据压缩率和磁盘I/O效率。
    *   **快速聚合**: 当需要对所有设备的某个度量进行聚合查询（如`SELECT AVG(temperature) FROM weather_stable`）时，数据库只需扫描一个连续的数据块，而无需像传统数据库那样扫描所有独立的表，性能提升显著。
    *   **灵活查询**: 标签（TAGS）使得查询变得极其灵活。用户可以轻松地根据设备属性进行过滤和分组，例如`SELECT * FROM weather_stable WHERE location='Beijing' GROUP BY device_id`。

2.  **关系与行为**:
    *   **继承关系**: 子表继承超级表的度量列定义。对超级表的结构修改（如增加度量列）会自动应用到所有现有和未来的子表。
    *   **独立性**: 每个子表拥有自己独立的标签值，这些值描述了该子表（设备）的唯一属性。
    *   **级联删除**: 删除超级表会同时删除其所有子表，确保了数据的一致性。

通过`test_subtable_query.py`中的测试用例可以验证，向超级表插入数据时，实际上是向其子表插入数据，而查询超级表则会返回所有子表的合并结果。
