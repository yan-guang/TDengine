## 引言

本文档旨在详尽地阐述 TDengine 数据库中的超级表（STABLE）这一核心数据模型。超级表是 TDengine 为解决物联网（IoT）场景下海量设备管理难题而设计的关键特性。它通过将具有相同度量（metric）但不同静态属性（tag）的设备数据进行高效组织，实现了数据模型的复用和高效的元数据管理。本文档将基于 `sql.y` 语法文件，系统性地文档化 `CREATE STABLE` 和 `DROP STABLE` 等数据定义语言（DDL）语句，并通过 `test/cases/04-SuperTables` 中的测试用例来验证其行为。

## 超级表概念

超级表（Super Table）是 TDengine 中一个抽象的、逻辑上的数据模型模板。它本身不直接存储时序数据，而是定义了一组子表（Child Table）所共有的数据结构。一个超级表由两部分组成：

1.  **度量列（Metric Columns）**：也称为数据列，用于存储随时间变化的时序数据，如温度、湿度、电压等。这些列在所有由该超级表创建的子表中是完全相同的。
2.  **标签列（Tag Columns）**：用于存储设备的静态属性，如设备ID、位置、型号等。这些属性不随时间变化，但不同设备的值可能不同。

通过超级表，用户可以为成千上万个设备创建结构一致的子表，每个子表继承超级表的度量列定义，并通过唯一的标签值来区分。这种设计极大地简化了海量设备的建模和管理，避免了为每个设备单独创建和维护表结构的复杂性。

## CREATE STABLE 语法详解

`CREATE STABLE` 语句用于创建一个超级表。其完整语法结构如下：

```sql
CREATE STABLE [IF NOT EXISTS] table_name 
    (column_def_list) 
    TAGS (tag_def_list) 
    [table_options];
```

根据 `sql.y` 语法文件中的定义，各部分的详细说明如下：

- **`CREATE STABLE`**: 固定关键字，用于声明创建超级表。
- **`[IF NOT EXISTS]`**: 可选子句。如果指定，当同名的超级表已存在时，不会报错，而是直接忽略该语句。
- **`table_name`**: 超级表的名称，遵循 TDengine 的命名规则。
- **`column_def_list`**: 度量列定义列表。由一个或多个 `column_def` 组成，每个 `column_def` 定义了列名、数据类型和可选的列选项。数据类型支持 `BOOL`, `TINYINT`, `SMALLINT`, `INT`, `BIGINT`, `FLOAT`, `DOUBLE`, `BINARY(N)`, `NCHAR(N)`, `TIMESTAMP` 等。
- **`TAGS (tag_def_list)`**: 标签列定义列表。由一个或多个 `tag_def` 组成，每个 `tag_def` 定义了标签列名和数据类型。标签列的数据类型与度量列类似，但有特定限制（例如，不能是 `TIMESTAMP`）。
- **`[table_options]`**: 可选的表选项，如 `COMMENT`（注释）、`TTL`（生存时间）等。

**语法解析规则**:
在 `sql.y` 文件中，`CREATE STABLE` 语句的语法规则定义如下：
```yacc
cmd ::= CREATE STABLE not_exists_opt(A) full_table_name(B)
  NK_LP column_def_list(C) NK_RP tags_def(D) table_options(E). 
  { pCxt->pRootNode = createCreateTableStmt(pCxt, A, B, C, D, E); }
```
此规则表明，`CREATE STABLE` 语句由 `CREATE STABLE` 关键字、可选的 `IF NOT EXISTS`、表名、括号内的度量列定义列表、`TAGS` 关键字和括号内的标签列定义列表，以及可选的表选项组成。当解析器匹配到此规则时，会调用 `createCreateTableStmt` 函数来创建相应的语法树节点。

## DROP STABLE 语法

`DROP STABLE` 语句用于删除一个超级表。其语法结构如下：

```sql
DROP STABLE [IF EXISTS] table_name;
```

- **`DROP STABLE`**: 固定关键字，用于声明删除超级表。
- **`[IF EXISTS]`**: 可选子句。如果指定，当要删除的超级表不存在时，不会报错。
- **`table_name`**: 要删除的超级表的名称。

删除超级表是一个非常危险的操作。它不仅会删除超级表本身的元数据，还会级联删除所有由该超级表创建的子表及其所有数据。因此，执行此操作前必须非常谨慎。

**语法解析规则**:
在 `sql.y` 文件中，`DROP STABLE` 语句的语法规则定义如下：
```yacc
cmd ::= DROP STABLE with_opt(A) exists_opt(B) full_table_name(C). 
  { pCxt->pRootNode = createDropSuperTableStmt(pCxt, A, B, C); }
```
此规则表明，`DROP STABLE` 语句由 `DROP STABLE` 关键字、可选的 `WITH` 子句（在当前版本中未使用）、可选的 `IF EXISTS` 和表名组成。当解析器匹配到此规则时，会调用 `createDropSuperTableStmt` 函数。

## 使用示例与测试验证

以下是一个创建和使用超级表的完整示例，并通过测试用例验证其行为。

### 创建超级表

假设我们要监控多个城市的气象站。所有气象站都测量温度（`temperature`）和湿度（`humidity`），但每个气象站的位置（`location`）和海拔（`altitude`）不同。

```sql
-- 创建数据库
CREATE DATABASE weather_db;
USE weather_db;

-- 创建超级表
CREATE STABLE weather_stable (
    ts TIMESTAMP, 
    temperature FLOAT, 
    humidity INT
) TAGS (
    location NCHAR(50), 
    altitude INT
);
```

### 创建子表并插入数据

基于 `weather_stable` 超级表，我们可以为每个气象站创建子表。

```sql
-- 为北京气象站创建子表
CREATE TABLE beijing_station USING weather_stable 
    TAGS ('Beijing', 50);

-- 为上海气象站创建子表
CREATE TABLE shanghai_station USING weather_stable 
    TAGS ('Shanghai', 10);

-- 向子表插入数据
INSERT INTO beijing_station VALUES (NOW, 25.5, 60);
INSERT INTO shanghai_station VALUES (NOW, 28.0, 75);
```

## 标签列在查询中的作用

标签列是超级表强大查询能力的核心。它们允许用户在不指定具体子表名的情况下，对所有子表的数据进行聚合和过滤。

### 基于标签的查询

用户可以直接在超级表上执行 `SELECT` 语句，并在 `WHERE` 子句中使用标签列进行条件筛选。

```sql
-- 查询所有位于北京的气象站的数据
SELECT * FROM weather_stable WHERE location = 'Beijing';

-- 查询海拔高于30米的气象站的平均温度
SELECT AVG(temperature) FROM weather_stable WHERE altitude > 30;
```

### 基于标签的聚合

`GROUP BY` 子句可以使用标签列，从而对具有相同标签值的设备组进行聚合分析。

```sql
-- 按城市分组，计算每个城市的平均湿度
SELECT location, AVG(humidity) FROM weather_stable GROUP BY location;
```

## 超级表作为模板

超级表的核心价值在于其作为“模板”的角色。它实现了数据模型的复用和高效的元数据管理。

### 数据模型复用

在物联网场景中，成千上万的设备通常具有相同的传感器类型（即相同的度量列）。通过定义一个超级表，管理员可以一次性定义所有设备的公共数据结构。每当需要添加一个新设备时，只需创建一个子表并指定其唯一的标签值即可，无需重复定义度量列。这极大地提高了数据建模的效率和一致性。

### 高效的元数据管理

TDengine 的元数据管理机制与超级表紧密集成。超级表的元数据（列定义、标签定义）被集中存储和管理。当对超级表进行 `ALTER` 操作（如添加一个新度量列）时，该变更会自动传播到所有子表，确保了数据结构的一致性。这种集中式管理避免了在海量子表上进行逐个修改的低效操作。

### 解决海量设备管理难题

传统的数据库为每个设备创建一个独立的表，会导致元数据爆炸，管理极其困难。超级表通过“一表多列”（一个超级表对应多个子表）的模式，将海量设备的管理问题转化为对少数超级表的管理问题，从根本上解决了海量设备的管理难题。

## 结论

超级表是 TDengine 数据库的核心创新之一，它完美地契合了物联网和时序数据场景的需求。通过将度量列和标签列分离，超级表提供了一种高效、灵活且易于管理的数据建模方式。`CREATE STABLE` 和 `DROP STABLE` 语句是管理超级表的基础，其语法清晰且功能强大。标签列不仅用于区分设备，更是实现跨设备数据聚合和分析的关键。超级表作为模板的角色，实现了数据模型的复用和元数据的集中管理，有效解决了海量设备带来的管理挑战。开发者应充分利用超级表的特性，以构建高性能、可扩展的时序数据应用。
