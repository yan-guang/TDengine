## 引言
TDengine 是一款专为时序数据设计的高性能数据库，其核心优势在于对时间序列数据的高效处理与分析。为了满足复杂的时序分析需求，TDengine 提供了一系列特有的时序分析子句，包括 `INTERVAL`（时间窗口）、`SESSION_WINDOW`（会话窗口）、`STATE_WINDOW`（状态窗口）和 `FILL`（填充模式）。这些子句极大地增强了 SQL 查询在处理时间序列数据时的能力，使得用户能够轻松地进行聚合、分组、补全等操作。

本文档旨在基于 `sql.y` 语法文件和 `test/cases/24-TimeSeriesExtensions` 中的测试用例，系统性地文档化这些时序分析功能。我们将详细说明每个子句的语法结构、参数含义、具体作用，并通过实际应用场景的示例来展示其使用方法。

## INTERVAL时间窗口

`INTERVAL` 子句是 TDengine 时序分析的核心，它允许用户将连续的时间序列数据按照指定的时间间隔进行分组，从而对每个时间窗口内的数据进行聚合计算。

### 语法与参数
根据 `sql.y` 语法文件，`INTERVAL` 子句的基本语法如下：
```
INTERVAL (duration [, offset])
```
- **duration**: 必需参数，定义了时间窗口的长度。它是一个持续时间（duration），可以使用 `a`（毫秒）、`s`（秒）、`m`（分钟）、`h`（小时）、`d`（天）、`w`（周）、`n`（月）、`y`（年）等单位。例如，`1m` 表示一分钟，`5s` 表示五秒。
- **offset**: 可选参数，定义了时间窗口的偏移量。它同样是一个持续时间。例如，`interval(1m, 30s)` 表示每分钟一个窗口，但窗口的起始时间从每分钟的第30秒开始。

此外，`INTERVAL` 子句通常与 `sliding`（滑动步长）结合使用，以实现滑动窗口分析。`sliding` 参数定义了窗口移动的步长。

### 具体作用
`INTERVAL` 子句的主要作用是将时间轴分割成一系列等长的、连续的（或滑动的）时间片段。对于每个片段，可以执行 `COUNT`、`SUM`、`AVG`、`MAX`、`MIN` 等聚合函数，从而得到该时间段内的统计结果。这在计算每分钟平均值、每小时最大值等场景中非常有用。

## SESSION_WINDOW会话窗口

`SESSION_WINDOW` 子句用于识别和分析“会话”周期。一个会话是指一系列在时间上紧密相连的事件，当事件之间的间隔超过预设的“间隙”（gap）时，会话即告结束。

### 语法与参数
根据 `sql.y` 语法文件和 `parAstCreater.c` 中的实现，`SESSION_WINDOW` 的语法如下：
```
SESSION_WINDOW (timestamp_column, gap_duration)
```
- **timestamp_column**: 必需参数，指定用于计算时间间隔的时间戳列。通常为 `ts`。
- **gap_duration**: 必需参数，定义了会话的“间隙”时长。如果两个连续事件的时间差大于此值，则认为前一个会话结束，新的会话开始。

### 具体作用
`SESSION_WINDOW` 的核心作用是根据事件的活跃程度来动态划分数据。它不依赖于固定的日历时间，而是基于数据本身的特性。例如，在用户行为分析中，可以将用户在应用内的一系列操作视为一个会话，当用户长时间无操作后再次进入，则视为新的会话。这在分析用户活跃度、设备使用周期等场景中非常有效。

## STATE_WINDOW状态窗口

`STATE_WINDOW` 子句用于根据某个状态列（或表达式）的变化来划分数据。当状态列的值发生变化时，即认为进入了一个新的状态窗口。

### 语法与参数
根据 `sql.y` 语法文件和 `parAstCreater.c` 中的实现，`STATE_WINDOW` 的基本语法如下：
```
STATE_WINDOW (state_expression [, extend_option] [, true_for_limit])
```
- **state_expression**: 必需参数，可以是一个列名或一个表达式，其值的变化将触发新窗口的开始。
- **extend_option**: 可选参数，用于控制窗口边界的扩展方式，例如 `FORWARD`、`BACKWARD` 或 `DEFAULT`。
- **true_for_limit**: 可选参数，用于限制状态为 `true` 的最小持续时间。

### 具体作用
`STATE_WINDOW` 的作用是将数据按照其“状态”进行分组。例如，在监控系统中，可以根据设备的 `status` 列（如 `running`、`stopped`）来划分数据，从而计算设备在每种状态下的持续时间。这在处理状态变化、计算状态持续时间等场景中至关重要。

## FILL填充模式

`FILL` 子句用于处理时间序列数据中的缺失值。当使用 `INTERVAL` 进行分组时，某些时间窗口可能没有数据，`FILL` 子句可以指定如何填充这些空窗口。

### 语法与参数
根据 `sql.y` 语法文件和 `test_fill.py` 测试用例，`FILL` 子句的语法如下：
```
FILL (fill_method [, fill_value1, fill_value2, ...])
```
- **fill_method**: 填充策略，支持多种模式：
  - `NULL`: 用 `NULL` 值填充。
  - `NONE`: 不填充，直接跳过空窗口。
  - `PREV`: 用前一个非空窗口的值填充。
  - `NEXT`: 用后一个非空窗口的值填充。
  - `LINEAR`: 使用线性插值法填充。
  - `VALUE`: 用指定的常量值填充。
- **fill_value**: 当 `fill_method` 为 `VALUE` 时，需要指定一个或多个具体的填充值，其数量必须与 `SELECT` 子句中聚合函数的数量一致。

### 具体作用
`FILL` 子句的作用是确保查询结果的连续性和平滑性。它避免了因数据缺失而导致的图表断点或分析偏差。例如，在绘制每分钟的平均值曲线时，如果某分钟没有数据，使用 `FILL(PREV)` 可以让曲线保持前一分钟的值，从而形成一条连续的线。

## 应用场景示例

### 计算每分钟的平均值
使用 `INTERVAL` 和 `FILL` 子句，可以轻松计算每分钟的平均值，并用前一个值填充缺失点。
```sql
SELECT _wstart, AVG(value) FROM sensor_data 
WHERE ts >= '2023-10-01 00:00:00' AND ts < '2023-10-01 01:00:00' 
INTERVAL(1m) FILL(PREV);
```

### 识别设备的会话周期
使用 `SESSION_WINDOW` 子句，可以根据设备上报数据的时间间隔来识别其会话。
```sql
SELECT _wstart, _wend, COUNT(*) FROM device_logs 
SESSION_WINDOW(ts, 5m) 
WHERE device_id = 'device_001';
```

### 处理状态变化
使用 `STATE_WINDOW` 子句，可以分析设备在不同状态下的持续时间。
```sql
SELECT _wstart, _wend, status, COUNT(*) FROM device_status 
STATE_WINDOW(status) 
WHERE device_id = 'device_001';
```

### 填补缺失数据点
使用 `FILL(VALUE, 0)` 可以将所有空窗口的计数填充为0。
```sql
SELECT _wstart, COUNT(*) FROM event_log 
INTERVAL(1h) FILL(VALUE, 0);
```

## 结论
TDengine 的 `INTERVAL`、`SESSION_WINDOW`、`STATE_WINDOW` 和 `FILL` 子句为时序数据分析提供了强大而灵活的工具。通过理解这些子句的语法和作用，用户可以构建出高效的查询，以满足从简单聚合到复杂行为分析的各种需求。结合 `test/cases/24-TimeSeriesExtensions` 中的测试用例，开发者可以快速掌握并应用这些功能。
