## 引言
TDengine客户端API提供了一套全面的错误处理机制，用于帮助开发者识别和处理在与数据库交互过程中可能遇到的各种问题。本文档旨在系统性地文档化所有错误码及其含义，解释`taos_errno`和`taos_errstr`等错误查询函数的使用方法，并提供错误分类、处理策略以及错误恢复模式。通过分析`include/util/taoserror.h`中的定义和`examples/c/demo.c`中的实践示例，本文档将指导开发者构建健壮的错误处理逻辑。

## 错误码分类与详细说明
TDengine的错误码按照不同的模块和功能进行了分类，每个错误码都有其特定的含义。以下是主要的错误码分类及其详细说明：

### 连接错误
连接错误通常发生在客户端尝试与TDengine服务器建立连接时。

- **TSDB_CODE_RPC_NETWORK_UNAVAIL**: 网络不可用，无法连接到服务器。
- **TSDB_CODE_RPC_TIMEOUT**: 连接超时。
- **TSDB_CODE_RPC_BROKEN_LINK**: 连接中断。
- **TSDB_CODE_RPC_PORT_EADDRINUSE**: 端口已被占用。
- **TSDB_CODE_RPC_FQDN_ERROR**: FQDN（完全限定域名）解析错误。

### 查询错误
查询错误发生在执行SQL查询时，可能是由于语法错误或数据问题导致。

- **TSDB_CODE_TSC_SQL_SYNTAX_ERROR**: SQL语法错误。
- **TSDB_CODE_TSC_DB_NOT_SELECTED**: 未选择数据库。
- **TSDB_CODE_TSC_EXCEED_SQL_LIMIT**: SQL语句长度超过限制。
- **TSDB_CODE_TSC_LINE_SYNTAX_ERROR**: 行协议语法错误。
- **TSDB_CODE_QRY_INVALID_QHANDLE**: 无效的查询句柄。

### 权限错误
权限错误发生在用户尝试执行没有足够权限的操作时。

- **TSDB_CODE_MND_NO_RIGHTS**: 用户没有足够的权限。
- **TSDB_CODE_MND_USER_DISABLED**: 用户被禁用。
- **TSDB_CODE_MND_AUTH_FAILURE**: 认证失败。
- **TSDB_CODE_TSC_NO_WRITE_AUTH**: 没有写入权限。
- **TSDB_CODE_PAR_PERMISSION_DENIED**: 权限被拒绝。

### 数据库操作错误
数据库操作错误涉及数据库的创建、删除、修改等操作。

- **TSDB_CODE_MND_DB_ALREADY_EXIST**: 数据库已存在。
- **TSDB_CODE_MND_DB_NOT_EXIST**: 数据库不存在。
- **TSDB_CODE_MND_TOO_MANY_DATABASES**: 数据库数量过多。
- **TSDB_CODE_MND_DB_IN_DROPPING**: 数据库正在被删除。
- **TSDB_CODE_MND_DB_IN_CREATING**: 数据库正在创建中。

### 表操作错误
表操作错误涉及表的创建、删除、修改等操作。

- **TSDB_CODE_MND_STB_ALREADY_EXIST**: 超级表已存在。
- **TSDB_CODE_MND_STB_NOT_EXIST**: 超级表不存在。
- **TSDB_CODE_MND_TOO_MANY_TAGS**: 标签数量过多。
- **TSDB_CODE_MND_TOO_MANY_COLUMNS**: 列数量过多。
- **TSDB_CODE_MND_TAG_ALREADY_EXIST**: 标签已存在。
- **TSDB_CODE_MND_TAG_NOT_EXIST**: 标签不存在。
- **TSDB_CODE_MND_COLUMN_ALREADY_EXIST**: 列已存在。
- **TSDB_CODE_MND_COLUMN_NOT_EXIST**: 列不存在。

### 其他错误
其他错误包括系统错误、配置错误等。

- **TSDB_CODE_OUT_OF_MEMORY**: 内存不足。
- **TSDB_CODE_FILE_CORRUPTED**: 文件损坏。
- **TSDB_CODE_INVALID_CFG**: 无效的配置。
- **TSDB_CODE_INVALID_PARA**: 无效的参数。
- **TSDB_CODE_INTERNAL_ERROR**: 内部错误。

## 错误查询函数
TDengine提供了两个主要的错误查询函数：`taos_errno`和`taos_errstr`，用于获取最近一次操作的错误码和错误信息。

### taos_errno
`taos_errno`函数返回最近一次操作的错误码。如果操作成功，返回值为0；如果操作失败，返回值为负数。

```c
int taos_errno(TAOS_RES *res);
```

- **参数**: `res` - 查询结果指针。
- **返回值**: 错误码。

### taos_errstr
`taos_errstr`函数返回最近一次操作的错误信息字符串。如果操作成功，返回值为"success"；如果操作失败，返回具体的错误信息。

```c
const char *taos_errstr(TAOS_RES *res);
```

- **参数**: `res` - 查询结果指针。
- **返回值**: 错误信息字符串。

## 错误处理策略与恢复模式
为了构建健壮的应用程序，开发者需要制定有效的错误处理策略和恢复模式。以下是一些常见的错误处理策略和恢复模式：

### 重试机制
对于某些临时性错误，如网络超时或连接中断，可以采用重试机制。在重试之前，建议等待一段时间以避免频繁重试导致的问题。

```c
for (i = 0; i < 5; i++) {
    if (NULL != pSql) {
        taos_free_result(pSql);
        pSql = NULL;
    }

    pSql = taos_query(taos, command);
    code = taos_errno(pSql);
    if (0 == code) {
        break;
    }
    sleep(1); // 等待1秒后重试
}
```

### 降级处理
对于某些关键操作，如果无法立即恢复，可以考虑降级处理。例如，当数据库不可用时，可以将数据暂存到本地文件或内存中，待数据库恢复后再进行同步。

### 日志记录
记录详细的错误日志有助于问题的诊断和解决。建议在捕获到错误时，记录错误码、错误信息以及相关的上下文信息。

```c
if (code != 0) {
    fprintf(stderr, "Failed to run %s, reason: %s\n", command, taos_errstr(pSql));
    taos_free_result(pSql);
    taos_close(taos);
    exit(EXIT_FAILURE);
}
```

### 异常处理
对于不可恢复的错误，如认证失败或权限不足，应立即终止操作并通知用户。可以通过抛出异常或返回错误码的方式进行处理。

在连接数据库时，如果连接失败，会打印错误信息并退出程序。

```c
TAOS *taos = taos_connect(argv[1], "root", "taosdata", NULL, 0);
if (taos == NULL) {
    printf("failed to connect to server, reason:%s\n", taos_errstr(NULL));
    exit(1);
}
```

### 执行查询
在执行查询时，如果查询失败，会打印错误信息并退出程序。

```c
TAOS_RES *result1 = taos_query(taos, qstr);
if (result1 == NULL || taos_errno(result1) != 0) {
    printf("failed to insert row, reason:%s\n", taos_errstr(result1));
    taos_free_result(result1);
    exit(1);
} else {
    printf("insert row: %i\n", i);
}
taos_free_result(result1);
```
