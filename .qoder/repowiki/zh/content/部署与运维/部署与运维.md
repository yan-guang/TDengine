## 配置文件详解

TDengine 的核心配置文件 `taos.cfg` 位于 `packaging/cfg/` 目录下，定义了系统运行的关键参数。以下为关键参数说明及调优建议。

### maxSQLLength
- **说明**：设置允许执行的 SQL 语句最大长度（单位：字节）。默认值为 1048576（1MB）。
- **调优建议**：若应用涉及大量批量写入或复杂查询，可适当增大该值。但需注意过大的 SQL 可能导致内存消耗增加或网络传输延迟，建议根据实际业务场景调整，一般不建议超过 10MB。

### asyncLog
- **说明**：日志写入模式开关。`1` 表示异步写入，`0` 表示同步写入。
- **调优建议**：生产环境推荐设置为 `1`，以提升系统性能，避免日志写入阻塞主流程。若对日志实时性要求极高（如审计场景），可设为 `0`，但会牺牲一定性能。

### 其他关键参数
- **fqdn**：当前节点的主机名或 IP 地址，必须正确配置以确保集群通信。
- **serverPort**：服务监听端口，默认 `6030`，可修改但需确保端口未被占用。
- **dataDir**：数据存储目录，默认 `/var/lib/taos`，建议挂载高性能磁盘并确保足够空间。
- **logDir**：日志目录，默认 `/var/log/taos`，建议独立挂载以避免日志占用数据盘空间。
- **monitor**：是否启用系统监控，`1` 启用，`0` 禁用。建议保持启用以便通过 keeper 收集指标。
- **compressMsgSize**：RPC 消息压缩阈值。`-1` 不压缩，`0` 全部压缩，`>0` 超过该值的消息才压缩。建议设为 `1024`（1KB）以平衡网络与 CPU 开销。
- **timezone**：系统时区，推荐设置为 `Asia/Shanghai` 以避免时区混乱。
- **locale** 和 **charset**：建议设置为 `zh_CN.UTF-8` 和 `UTF-8` 以支持中文环境。

## 单机与集群部署

### 单机部署
1. 安装 TDengine 软件包（RPM/DEB 或源码编译）。
2. 修改 `taos.cfg` 配置文件，确保 `fqdn`、`dataDir`、`logDir` 等路径正确。
3. 启动服务：`sudo systemctl start taosd`。
4. 验证服务：`taos` 进入客户端，执行 `show dnodes;` 查看节点状态。

### 分布式集群部署
1. 在所有节点安装 TDengine。
2. 在第一个节点配置 `taos.cfg`：
   - 设置 `fqdn` 为本机 IP 或主机名。
   - 设置 `firstEp` 为 `本机IP:6030`。
3. 启动第一个节点：`sudo systemctl start taosd`。
4. 在其余节点配置 `taos.cfg`：
   - 设置 `fqdn` 为各自 IP。
   - 设置 `firstEp` 为第一个节点的 `IP:6030`。
5. 依次启动其余节点。
6. 登录任一节点，执行 `show dnodes;` 和 `show mnodes;` 验证集群状态。

## keeper监控工具配置与使用

`taosKeeper` 是 TDengine 3.0 引入的监控指标导出工具，用于收集集群运行状态并写入 TDengine 数据库，便于统一监控。

### 配置文件
配置文件位于 `tools/keeper/config/taoskeeper.toml`，主要配置项如下：
- **host/port**：keeper 监听地址和端口，默认 `6043`。
- **[tdengine]**：连接 TDengine 的参数，包括 `host`、`port`、`username`、`password`。
- **[metrics]**：指标配置，`prefix` 为指标前缀，`database.name` 为存储指标的数据库名。
- **[log]**：日志配置，可设置日志级别、保留天数、压缩等。

### 使用步骤
1. 确保 TDengine 和 taosAdapter 已启动。
2. 编译 keeper：在 `tools/keeper` 目录下执行 `go build`。
3. 修改 `taoskeeper.toml` 配置文件，确保连接信息正确。
4. 启动 keeper：`./taoskeeper`。
5. keeper 会自动创建 `log` 数据库并写入监控数据。

## Prometheus与Grafana集成监控

通过 keeper 可将 TDengine 指标暴露给 Prometheus，再通过 Grafana 可视化。

### Prometheus 配置
在 `tools/keeper/prometheus/prometheus.yml` 中添加 job：
```yaml
- job_name: "taoskeeper"
  static_configs:
    - targets: ["taoskeeper:6043"]
```
此配置使 Prometheus 定期从 keeper 的 `6043` 端口抓取指标。

### Grafana 配置
1. 导入 `tools/keeper/dashboards/tdengine-taoskeeper-prometheus-dashboard.json` 仪表板。
2. 配置 Prometheus 数据源。
3. 仪表板包含集群概览、DNode/MNode 状态、数据库/表数量、连接数、资源使用等关键指标。

### 仪表板功能
- **集群状态**：显示 First EP、版本、主节点运行时间、授权信息。
- **资源概览**：DNode、MNode、数据库、表、连接数统计。
- **性能监控**：CPU、内存、磁盘、网络等系统资源使用情况。
- **企业版授权**：显示授权到期时间及已用测点数。

## 日志管理

### 日志位置
日志默认存储在 `logDir` 配置的目录下，通常为 `/var/log/taos/`，主要日志文件包括：
- `taosd.log`：主服务日志。
- `taosadapter.log`：适配器日志。
- `keeper.log`：keeper 工具日志。

### 日志级别
通过 `debugFlag` 参数控制日志级别：
- `131`：仅输出警告和错误。
- `135`：输出调试、警告和错误。
- `143`：输出跟踪、调试、警告和错误到日志文件。
- `199`：输出调试、警告和错误到屏幕和文件。
- `207`：输出跟踪、调试、警告和错误到屏幕和文件。

### 日志轮转
通过 `logKeepDays`、`rotationCount`、`rotationSize` 控制日志保留策略，避免磁盘被占满。

## 备份与恢复

### 备份策略
1. **逻辑备份**：使用 `SELECT INTO` 或 `taosdump` 工具导出数据。
2. **物理备份**：直接复制 `dataDir` 目录下的数据文件，需在服务停止状态下进行以保证一致性。

### 使用 taosdump
```bash
# 备份所有数据库
taosdump -o /backup/path --all

# 恢复备份
taosdump -i /backup/path
```

### 恢复步骤
1. 停止 TDengine 服务。
2. 清理目标数据目录（可选）。
3. 将备份文件复制到 `dataDir`。
4. 启动服务。
